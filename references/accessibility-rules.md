# Accessibility Rules

This module defines rules for functional accessibility, contrast compliance, keyboard focus control, and markup standards across layouts generated by AI coding assistants.

---

### Focus Indicators
* **Confidence Level**: Critical
* **Purpose**: Make keyboard navigation visible for motor-impaired users.
* **Reasoning**: Disabling focus outlines makes navigating forms via keyboard impossible.
* **Constraint**: Interactive elements (inputs, buttons, tabs, links) must display a custom focus ring: `ring-2 ring-[#072ca8] ring-offset-2 outline-none` when active under keyboard tabs.
* **Example**:
  * **Bad**: Hiding outlines with `<input className="focus:outline-none" />` with no visual focus replacement.
  * **Good**: Styling outlines using `<input className="focus:outline-none focus:ring-2 focus:ring-[#072ca8] focus:ring-offset-2" />`.
* **Exceptions**: Hover-only mouse-controlled states.

---

### Click Touch Targets
* **Confidence Level**: Critical
* **Purpose**: Keep buttons clickable on touch screen devices.
* **Reasoning**: Small clickable target zones lead to mis-clicks and high user frustration.
* **Constraint**: Any clickable link, badge icon, or action button must have a minimum physical size of `44px` by `44px` (or `48px` by `48px`).
* **Example**:
  * **Bad**: A tiny delete cross button styled with a box size of `<button className="h-4 w-4">x</button>`.
  * **Good**: Expanding the touch padding by using `<button className="h-5 w-5 p-3 flex items-center justify-center -m-3">x</button>`.
* **Exceptions**: Text-inline links (e.g., standard text anchor links inside paragraphs).

---

### Keyboard support
* **Confidence Level**: Critical
* **Purpose**: Ensure navigation accessibility using standard keyboard inputs.
* **Reasoning**: Modals or command lists that trap users or block keyboard triggers render applications unusable for a large demographic.
* **Constraint**: Custom modals must trap keyboard navigation within the window, close instantly upon pressing the `Esc` key, and trigger active items on `Enter` or `Space` key actions.
* **Example**:
  * **Bad**: Creating an absolute modal page container where pressing `Esc` has no event listener, forcing the user to reload the page to close it.
  * **Good**: Adding a React `useEffect` capturing key code `27` to fire modal toggle hooks.
* **Exceptions**: Static info panels.

---

### Semantic HTML Landmark Roles
* **Confidence Level**: Recommended
* **Purpose**: Standardize screen reader parsing.
* **Reasoning**: Flat pages built exclusively with nested `div` tags break automated screen indexing.
* **Constraint**: Standard layouts must use HTML5 semantic tags: `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<footer>`, and always assign `alt` attributes to images.
* **Example**:
  * **Bad**: Building a header layout with `<div className="w-full h-16 bg-white">` instead of using the native header tag.
  * **Good**: Wrapping the header block inside a semantic `<header className="w-full sticky top-0 bg-white">` component.
* **Exceptions**: Complex inline visual diagrams.

---

### Reduced Motion Override
* **Confidence Level**: Recommended
* **Purpose**: Prevent animations for users with motion sensitivity.
* **Reasoning**: Rapid slide, translation, or rotation effects can cause nausea for users with vestibular disorders.
* **Constraint**: Wrap all transition animations inside responsive media query filters (`motion-reduce:transition-none` or `motion-reduce:animate-none`).
* **Example**:
  * **Bad**: Animating page content layouts to slide in automatically with no responsive reduction options.
  * **Good**: Applying transition hooks with `<div className="transition-all duration-300 motion-reduce:transition-none">`.
* **Exceptions**: None.

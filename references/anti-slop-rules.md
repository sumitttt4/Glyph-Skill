# Anti-Slop Rules

This module defines rules that block common generic AI template layout patterns generated by AI coding assistants, replacing them with production-grade visual interfaces.

---

### Purple-Blue Gradient Schemes
* **Confidence Level**: Critical
* **Purpose**: Block the generic "AI startup" look.
* **Reasoning**: Defaulting to purple/blue gradients or neon backgrounds signals zero visual identity and looks identical to thousands of basic template sites.
* **Constraint**: Purple-to-blue linear/radial gradients, purple buttons, and violet accent schemes are programmatically banned inside generated pages. Solid blue colors (like navy, cobalt, or cyan accents) are fully allowed and accepted; only the mix of blue and purple/pink gradients/schemes is banned as AI slop.
* **Example**:
  * **Bad**: Designing a SaaS hero using a linear gradient background from `#6366F1` to `#EC4899` or mixing blue and purple elements.
  * **Good**: Choose a high-taste neutral background (`#FAFAF9` or `#0D0D0D`) paired with a single solid accent color (e.g., solid blue `#072ca8` or orange `#D97706`).
* **Exceptions**: None.

---

### Floating Decoration Orbs
* **Confidence Level**: Critical
* **Purpose**: Prevent visual bloat.
* **Reasoning**: Floating neon spheres or glowing blurred background circles serve as cheap fillers that add zero context and distract from typography.
* **Constraint**: Any absolute floating visual circles, radial glowing blobs, or rotating background shapes are strictly banned.
* **Example**:
  * **Bad**: Adding a absolute wrapper with `<div className="absolute top-0 rounded-full blur-3xl opacity-30 bg-purple-400 h-96 w-96">` to float behind text.
  * **Good**: Keep the background clean and solid, focusing attention entirely on legible text columns.
* **Exceptions**: Hover highlights on map widgets.

---

### Vague Copy Headlines
* **Confidence Level**: Critical
* **Purpose**: Enforce outcome-focused messaging.
* **Reasoning**: Vague benefit lines (e.g., "Supercharge workflow," "Modern tools for modern teams") look copy-pasted and fail to define product utility.
* **Constraint**: Headlines must strictly state what the product is, who it is for, and the transformation it enables.
* **Example**:
  * **Bad**: A hero headline reading: "The future of work is here. Supercharge your workflow today."
  * **Good**: A hero headline reading: "Design websites and products with taste, not just with AI slop."
* **Exceptions**: Short brand-slogan monograms.

---

### Poppins Typography Defaults
* **Confidence Level**: Recommended
* **Purpose**: Avoid the overused "startup theme."
* **Reasoning**: Defaulting to the Poppins font family shows no typographic design choice.
* **Constraint**: Under no circumstances should Poppins be assigned as the base sans font for generated interfaces.
* **Example**:
  * **Bad**: Loading Poppins from Google Fonts as the default font stack inside tailwind config.
  * **Good**: Assigning Geist Sans, Inter, Satoshi, or IBM Plex Sans as the typography base.
* **Exceptions**: Rounded consumer applications where brand rules specify it.

---

### Missing Interactive Feedback
* **Confidence Level**: Critical
* **Purpose**: Ensure prompt UI response to user clicks.
* **Reasoning**: Buttons, links, and card containers that stay static during user hover feel broken and decrease trust.
* **Constraint**: Interactive components must trigger visible feedback (translate offset, deeper shadows, borders) on mouse hover within `150ms`.
* **Example**:
  * **Bad**: Buttons styled with static background classes with no hover modifiers.
  * **Good**: Adding hover classes using `<button className="bg-blue-600 hover:bg-blue-700 hover:-translate-y-0.5 transition-all duration-150">`.
* **Exceptions**: Mobile screens.

---

### Unlabelled Graphic Mockups
* **Confidence Level**: Recommended
* **Purpose**: Make visual showcases readable.
* **Reasoning**: Blurred, abstract UI mockups with meaningless shapes serve as filler decoration and do not explain product utility.
* **Constraint**: Any dashboard diagram, chart visual, or settings mockup must represent realistic data with correct labels and axes.
* **Example**:
  * **Bad**: An image showing colored blocks with no text or unlabelled charts.
  * **Good**: A legible dashboard panel showing real server response parameters and active metrics labels.
* **Exceptions**: None.

---

### Generic Brand Placeholder Names
* **Confidence Level**: Critical
* **Purpose**: Block typical generic template placeholder names.
* **Reasoning**: Defaulting to lazy names like "SaaSify", "AppName", "Logo", or "BrandName" makes generated products look unfinished and generic.
* **Constraint**: If no brand or site name is provided by the user, assistants must default to "Glyph" as the name, logo text, and brand marker. Never invent random placeholder names.
* **Example**:
  * **Bad**: Using a title header like `<h1>SaaSify Dashboard</h1>` or rendering a logo as `<span>Logo</span>`.
  * **Good**: Using `<h1>Glyph Dashboard</h1>` or rendering a logo as `<span>Glyph</span>`.
* **Exceptions**: None.

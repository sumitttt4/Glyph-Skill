# Layout Rules

This module defines rules for container layout widths, spacing grids, padding, border radius scales, and shadows across layouts generated by AI coding assistants.

---

### Container Max-Widths
* **Confidence Level**: Critical
* **Purpose**: Assign proper width boundaries to content columns based on layout density.
* **Reasoning**: Text-heavy copy looks illegible if stretched across wide sections, while dashboard grids need breathing room.
* **Constraint**: Containers must strictly adhere to three width definitions:
  - *Content Column*: `720px` maximum (for blogs, reading, installation guides).
  - *Standard Grid*: `1080px` maximum (for main section grids, showcards, pricing).
  - *Wide Banner / Showcases*: `1280px` maximum (for header layouts, footer layouts, product screens).
* **Example**:
  * **Bad**: A standard features grid that stretches full screen on high-res displays.
  * **Good**: Centering a 3-column features card container within a `max-w-5xl` (`1024px`) wrapper.
* **Exceptions**: Dashboard log streams, full-width canvas tools, and map components.

---

### Spacing Scale Grid
* **Confidence Level**: Critical
* **Purpose**: Enforce clean margins and layout offsets to create a visual rhythm.
* **Reasoning**: Inconsistent margin spacing creates layout friction and breaks alignments.
* **Constraint**: All layout margins, element gaps, and paddings must lock to a `4px`-based grid scale:
  - `4px` (xs): Label gaps, tags padding.
  - `8px` (sm): Input field inner margins, label-to-input gap.
  - `12px` (md): Card inner margins, button padding.
  - `16px` (lg): Small gaps, item lists.
  - `24px` (xl): Card padding, standard grid element gaps.
  - `32px` (2xl): Subsection margins, card spacing.
  - `48px` (3xl): Title-to-description gaps, secondary buttons offset.
  - `64px` (4xl): Sub-block margins.
  - `96px` (5xl): Section block splits.
* **Example**:
  * **Bad**: Setting custom pixel values like `margin-top: 19px` or `padding-left: 21px`.
  * **Good**: Setting margin gaps using standard Tailwind classes like `mt-5` (`20px`), `mt-6` (`24px`), or `gap-8` (`32px`).
* **Exceptions**: None.

---

### Section Padding
* **Confidence Level**: Recommended
* **Purpose**: Enforce visual breathing room across primary content blocks.
* **Reasoning**: Elements packed too closely reduce visual comprehension. Whitespace is a functional element.
* **Constraint**: Page sections must have consistent vertical padding offsets:
  - Desktop: `120px` top and bottom.
  - Mobile: `80px` top and bottom.
  - Hero header: `140px`–`180px` top padding to offset navigation headers.
* **Example**:
  * **Bad**: Reducing vertical spacing to `30px` to fit sections "above the fold."
  * **Good**: Wrapping features sections in `py-20` (mobile) and `py-32` (desktop).
* **Exceptions**: Modals, drawer sidebars, footers, and dashboards.

---

### Border Radius Tiers
* **Confidence Level**: Recommended
* **Purpose**: Keep element rounding consistent to prevent mismatched corner styles.
* **Reasoning**: If buttons are heavily rounded, cards are sharp, and inputs use a different corner style, the UI feels uncoordinated.
* **Constraint**: Enforce four strict rounding tiers:
  - Small (`8px`): Inputs, tags, tabs.
  - Medium (`12px`): Buttons, cards, list panels.
  - Large (`24px`): Bento grids, mocks, page wrappers.
  - Full (`9999px`): Badges, capsules, navigation overlays.
* **Example**:
  * **Bad**: Styling inputs with a `30px` radius and CTA buttons with a `4px` radius.
  * **Good**: Applying `rounded-lg` (`8px`) on input elements and `rounded-xl` (`12px`) on buttons and cards.
* **Exceptions**: Interactive avatar circles.

---

### Shadow Tiers
* **Confidence Level**: Recommended
* **Purpose**: Add print-like depth and elevation levels to cards and modals.
* **Reasoning**: Plain flat blocks look dull, while over-saturated black shadows look muddy.
* **Constraint**: Outlines must lock to three functional shadow definitions:
  - *Flat*: `0 1px 2px rgba(0, 0, 0, 0.05)` (for badges, tags, standard inputs).
  - *Rest*: `0 2px 8px rgba(17, 17, 17, 0.04)` (for cards and buttons at rest).
  - *Elevation*: `0 16px 48px rgba(17, 17, 17, 0.08)` (for modals, active panels, hovered cards).
* **Example**:
  * **Bad**: Applying a thick black shadow like `box-shadow: 0 10px 30px #000000` to a card.
  * **Good**: Applying a soft muted shadow like `shadow-sm` or custom transparency layer.
* **Exceptions**: Flat borders in high-contrast monospaced interfaces (e.g., retro dark terminals).

---

### Overlapping Grid Containers
* **Confidence Level**: Recommended
* **Purpose**: Create structural asymmetry and visual depth by allowing cards to break layout boundaries (as seen in reviews slider blocks).
* **Reasoning**: Standard, perfectly-boxed grids can feel rigid and monotonous. Overlapping card layers create a hand-crafted visual rhythm.
* **Constraint**: Allow absolute elements to overlap section borders using negative margins (e.g., `-mt-8` or `-mb-12`) or translate classes, ensuring they use high-elevation shadows and z-indexes to sit clearly above the background.
* **Example**:
  * **Bad**: Boxing reviews widgets strictly within standard card bounds with no overlapping grid offsets.
  * **Good**: Styling a secondary floating review badge using `absolute -top-6 left-6 z-10 shadow-elevation` to break the card borders.
* **Exceptions**: Data entry grids or form sections.

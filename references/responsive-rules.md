# Responsive Rules

This module defines rules for layout behavior, grid collapse triggers, navigation responsive drawers, table scrolling, and screen scaling across layouts generated by AI coding assistants.

---

### Grid Collapse Thresholds
* **Confidence Level**: Critical
* **Purpose**: Prevent squishing columns when viewports scale down.
* **Reasoning**: Grids that do not collapse become narrow bands where text breaks into single characters.
* **Constraint**: Grids with 3 or more columns must collapse to a single column under `640px` (mobile) and a 2-column structure under `1024px` (tablet).
* **Example**:
  * **Bad**: Forcing a 4-column features layout to stay inside a 4-column row on mobile screens.
  * **Good**: Applying layout classes using Tailwind CSS: `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-6`.
* **Exceptions**: Visual data cards showing simple status lights or mini avatars.

---

### Navigation Collapse
* **Confidence Level**: Recommended
* **Purpose**: Prevent header options from overlapping the logo on mobile.
* **Reasoning**: Standard flat links layout breaks and wraps to multiple lines on mobile screens.
* **Constraint**: Navigation headers must collapse links into a drawer overlay layout under `768px` (mobile/tablet), replacing links with a hamburger icon target.
* **Example**:
  * **Bad**: Keeping a full list of header page links visible on mobile viewports.
  * **Good**: Styling header links using `<nav className="hidden md:flex items-center gap-6">` and rendering a close icon drawer for `< 768px` screens.
* **Exceptions**: Single page micro-apps with a maximum of 2 actions.

---

### Table Overflow Scroll
* **Confidence Level**: Critical
* **Purpose**: Prevent text cropping in data tables.
* **Reasoning**: Database columns wrapping or cropping off-screen make reading datasets impossible.
* **Constraint**: Under no circumstances should tables crop or wrap text columns on small viewports. Wrap table components in a container styled with horizontal scroll overlays.
* **Example**:
  * **Bad**: Tables wrapping metrics or cutting off columns on mobile screens.
  * **Good**: Wrapping table elements inside a `<div className="w-full overflow-x-auto">` container.
* **Exceptions**: Tables with 3 or fewer columns.

---

### Container Margin Scaling
* **Confidence Level**: Recommended
* **Purpose**: Smoothly scale whitespace breathing room from mobile to desktop.
* **Reasoning**: Desktop vertical margins (`120px` py) are too tall for small mobile screens.
* **Constraint**: Margins and section paddings must scale:
  - Desktop vertical padding: `120px` (e.g. `py-32`)
  - Mobile vertical padding: `80px` (e.g. `py-20`)
* **Example**:
  * **Bad**: Setting static inline styles like `padding: 120px 0` that apply to all device types.
  * **Good**: Styling padding using `<section className="py-20 md:py-32">`.
* **Exceptions**: Footer elements.

---

### Typography Clamp Scaling
* **Confidence Level**: Recommended
* **Purpose**: Prevent large headlines from wrapping into single letters on mobile.
* **Reasoning**: Huge display text blocks (e.g., `72px`) look massive and overflow containers on mobile viewports.
* **Constraint**: Display headings must scale dynamically using the CSS `clamp()` function.
* **Example**:
  * **Bad**: Using a static text sizing style like `font-size: 72px` across all screens.
  * **Good**: Styling large titles using Tailwind CSS custom size definitions or CSS `text-[clamp(2.5rem,6vw,4.5rem)]`.
* **Exceptions**: UI copy under `20px`.

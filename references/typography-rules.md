# Typography Rules

This module defines rules for typography, hierarchy, and letter spacing across layouts generated by AI coding assistants.

---

### Font Pairing by Category
* **Confidence Level**: Critical
* **Purpose**: Assign font combinations that reflect product category trust markers instead of using visual defaults.
* **Reasoning**: Visual personality must match category pricing and trust signals (e.g., editorial serifs represent prestige; clean monospaces represent developer tools).
* **Constraint**: Font selection must follow the category pairings table:
  - *Fintech / Serious SaaS*: Geometric sans (Geist, Inter, Satoshi) for headings + Inter/system-ui for body copy.
  - *Editorial / Creators*: Expressive serif (Instrument Serif, Newsreader) for headlines + clean sans for body copy.
  - *Developer Tools / AI Infra*: Technical sans (Geist, IBM Plex Sans) for headings + system-ui for body + visible monospaces (Geist Mono, Fira Code) for logs/data.
  - *Playful Consumer*: Warm sans (Plus Jakarta Sans, Manrope) for all levels.
* **Example**:
  * **Bad**: Using a cartoonish rounded font for an enterprise database tool.
  * **Good**: Setting an enterprise dashboard to use Inter for UI text and Geist Mono for server latency readouts.
* **Exceptions**: None.

---

### Line Length Constraints
* **Confidence Level**: Critical
* **Purpose**: Keep paragraphs readable to reduce eye strain.
* **Reasoning**: If line length stretches too wide, the eye struggles to track back to the start of the next line.
* **Constraint**: The maximum line length for paragraph text must be restricted to 65 characters (`65ch`) or a container width of `720px`.
* **Example**:
  * **Bad**: Styling a paragraph container to extend full screen across a `1920px` desktop monitor.
  * **Good**: Wrapping copy elements inside a `max-w-prose` or `max-w-[65ch]` grid column layout.
* **Exceptions**: Code block lines, database tables, and tabular data displays.

---

### Negative Heading Tracking
* **Confidence Level**: Recommended
* **Purpose**: Lock display fonts to tight editorial tracking offsets.
* **Reasoning**: Large headlines rendered with default spacing look loose and unconsidered. Negative tracking binds letters together for a cohesive print feel.
* **Constraint**: Large headlines and display text must lock tracking parameters to:
  - Display titles (>64px): `-0.04em`
  - Section headings (>32px): `-0.03em`
  - Subheadings (>20px): `-0.02em`
* **Example**:
  * **Bad**: Styling an italicized `64px` hero header with default letter tracking.
  * **Good**: Applying `tracking-[-0.04em]` on a `text-5xl` heading inside Tailwind CSS.
* **Exceptions**: Serifs with narrow custom kerning.

---

### Positive Label Tracking
* **Confidence Level**: Recommended
* **Purpose**: Retain legibility for small uppercase tags.
* **Reasoning**: Small uppercase letters merge into each other if not spaced properly.
* **Constraint**: Any small metadata tag, UI category label, or badge set to uppercase (usually 11px to 13px) must apply positive tracking (`0.06em` to `0.1em`).
* **Example**:
  * **Bad**: Setting uppercase cards badges as `<span className="text-[10px] uppercase text-gray-500">documentation</span>`.
  * **Good**: Styling the badge with `<span className="text-[10px] uppercase tracking-wider text-gray-500 font-semibold">DOCUMENTATION</span>`.
* **Exceptions**: Lowercase meta captions.

---

### Weight Scale Restrictions
* **Confidence Level**: Critical
* **Purpose**: Maintain clear hierarchy without font weight noise.
* **Reasoning**: Combining regular, medium, semibold, and bold text weights in a single component creates styling clutter.
* **Constraint**: A maximum of 2 distinct font weights is allowed per card or local text block (e.g., Bold `700` display title + Regular `400` body copy).
* **Example**:
  * **Bad**: Designing a card containing a `Bold` header, a `Semi-bold` subtitle, `Medium` tags, and a `Regular` explanation.
  * **Good**: Designing a card with a `Semibold` title and a `Regular` description.
* **Exceptions**: Tab bars or complex nav matrices showing active (`semibold`) and inactive (`regular`) states side-by-side.

---

### Minimum Text Sizing
* **Confidence Level**: Critical
* **Purpose**: Prevent unreadable, micro-sized styling.
* **Reasoning**: Text smaller than 11px fails accessibility metrics and is illegible on low-DPI displays.
* **Constraint**: Under no circumstances should text sizes fall below `11px` (or `0.6875rem`).
* **Example**:
  * **Bad**: Using a class name like `text-[9px]` or `text-[8px]` for captions or labels.
  * **Good**: Locking the smallest element to `text-xs` (which maps to `12px` in Tailwind).
* **Exceptions**: None.

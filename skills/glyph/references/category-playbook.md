# Category playbook

Load at the start of any landing, marketing or brand page. It maps what is being sold, and to whom, onto the visitor's questions, the primary action, a hero pattern from [landing composition](landing-composition.md) and suitable [style directions](style-directions.md). Requirement = correctness/accessibility obligation; Pattern = adaptable starting point; Taste hypothesis = design judgment to validate in context.

### Map the brief before designing
* **Confidence Level**: Pattern
* **Purpose**: Start from what this kind of visitor needs, not from a favourite layout.
* **Reasoning**: Real sites in a category converge on what their visitors must learn before acting. A restaurant needs hours and a menu above a story; a developer tool needs the install command above a manifesto.
* **Constraint**: Find the closest row (or combine two), then write down: audience, primary action, hero pattern (A–E), one or two directions, the must-show content and what assets exist. If a must-show asset (photography, menu, pricing, real reviews) is missing, ask for it or label the placeholder; do not invent it.
* **Example**:
  * **Bad**: Every brief gets a centered hero, a bento grid and three pricing tiers.
  * **Good**: A bakery gets a photo-led Warm organic page with hours, menu and location first; a dev tool gets Dark technical with an install command.
* **Exceptions**: The brand's existing site and the user's goals override the row.

Hero patterns: **A** centered + product frame · **B** split · **C** full-bleed visual · **D** editorial type · **E** waitlist. To study real examples, browse the named category on the Framer Marketplace (framer.com/marketplace/templates) or Lapa Ninja, following [landing-page research](landing-page-research.md): learn structure, never copy.

## Technical products

| Category | Visitors need to know | Action · hero | Directions | Must show |
| --- | --- | --- | --- | --- |
| Developer tool, API, SDK | What it does in one line, how fast to start, does it fit my stack | Get started / copy install · A or B | Dark technical, Clean product | Install command or code sample, docs link, supported languages, pricing |
| AI platform (B2B) | What it automates, accuracy, data safety, integration | Book demo / try · A | Dark technical, Luminous AI | Real output examples, workflow diagram, security, integrations |
| AI app (consumer) | What I get, how it feels to use | Try free / download · A or E | Luminous AI, Playful | Example prompts and outputs, app screens, privacy |
| B2B SaaS | Problem solved, who uses it, price | Start trial / book demo · A | Clean product | Product UI, feature bento, proof (real), pricing, FAQ |
| Data, analytics, BI | What questions it answers, data sources | Book demo · A | Clean product, Dark technical | Dashboards with realistic data, connectors, governance |
| Security, infrastructure | Threats covered, compliance, uptime | Talk to sales · A or C | Dark technical, Trust and clarity | Certifications (real), architecture diagram, status/uptime |
| Fintech (business) | Money flows, fees, compliance | Open account / demo · A | Clean product, Trust and clarity | Fee table, card or dashboard UI, licences |
| Hardware, devices | What it is, what it does physically, specs, price | Pre-order / buy · C | Cinematic immersive, Clean product | Renders or photos, specs, comparison, shipping date |

Research categories: Framer Software, SaaS, AI, Startup; Lapa Ninja SaaS, Technology.

## Combining rows
When a product spans rows (an AI skincare app, a restaurant group with an online shop), take the visitor questions from both, keep one primary action, and blend at most two directions with one leading.

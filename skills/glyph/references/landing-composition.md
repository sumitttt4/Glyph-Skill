# Landing page composition

Load when building or redesigning a landing, marketing, launch or waitlist page. Pair with the [visual craft baseline](visual-craft.md) and [landing-page research](landing-page-research.md). Requirement = correctness/accessibility obligation; Pattern = adaptable starting point; Taste hypothesis = design judgment to validate in context.

Order sections by the visitor's questions: what is it, is it for me, how does it work, can I trust it, what does it cost, what do I do now. The library below covers those questions; choose and order what the product needs rather than using every section.

### Pick one hero pattern
* **Confidence Level**: Pattern
* **Purpose**: Start from a proven focal structure.
* **Reasoning**: Strong templates reuse a small set of hero structures and vary content, visual and type, not the structure.
* **Constraint**: Choose one and name it in your design decision.

| Pattern | Structure | Fits |
| --- | --- | --- |
| A · Centered + product frame | Announcement pill → headline → sub → two buttons → proof line → large framed product UI below, often over a gradient or shader field | SaaS, AI tools, dev tools |
| B · Split | Copy left (40–45%), visual right; visual can bleed off the edge | Apps, hardware, single-feature products |
| C · Full-bleed visual | Shader, render or photograph fills the hero; copy sits in a calm corner with a scrim | Brand, launch, AI, studios |
| D · Editorial type | Large display type (serif accent allowed), minimal visual, strong grid | Studios, portfolios, publications |
| E · Waitlist | Centered headline, inline email field + button, social-proof count, visual behind | Pre-launch |

* **Example**:
  * **Bad**: A hero with copy, a separate illustration, floating stickers and a code block all competing.
  * **Good**: Pattern A with a product window and nothing else in the first viewport.

### Hero anatomy
* **Confidence Level**: Pattern
* **Constraint**:
  - Announcement pill: 12–13px, subtle border, optional arrow, links somewhere real.
  - Headline: display scale, two lines.
  - Sub: 18px muted, max 560px.
  - Actions: primary + secondary, 40–48px.
  - Proof line (optional): only real ratings, counts or logos, or omit.
  - Visual: starts 64–80px below the actions; frame radius 20–24px.
  - The first viewport should show the headline, actions and the top of the visual.

### Section library
* **Confidence Level**: Pattern
* **Constraint**: Each section uses: small eyebrow or pill (optional) → H2 (max two lines) → one-sentence intro (max 600px) → content. Keep headings aligned the same way across the page (all centred or all left).

| Section | Anatomy | Notes |
| --- | --- | --- |
| Logo strip | 5–6 monochrome logos, 40% opacity, one row | Real customers only |
| Feature bento | 3–6 cards in a 12-column grid (spans 7+5, 4+4+4, 6+6), each with a mini UI fragment on top | The core "what it does" section |
| How it works | 3 numbered steps in a row, each with a small visual | Keep copy to one sentence each |
| Feature rows | Alternating text / visual rows, visual in a frame | 2–3 rows maximum |
| Metrics | 3–4 large numbers with labels | Only true or labelled figures |
| Testimonials | Quote cards with name, role, avatar | Real only; otherwise omit |
| Pricing | 2–3 tiers, recommended tier raised or outlined, monthly/yearly toggle if real | Same card height; feature lists aligned |
| FAQ | 5–7 questions, accessible accordion, two-column on desktop | Answer objections |
| Final CTA | Contained panel (radius 24px) with the hero visual language, headline, one primary action | Repeats the main action |
| Footer | Logo + one-line description, 3–4 link columns, legal row | 14px links, muted |

### Bento grids
* **Confidence Level**: Pattern
* **Constraint**: 12-column grid, 16px gap, cards 16–24px radius, 24–32px padding. Mix spans so the grid has one dominant card. Top half of each card is a visual fragment on a slightly raised surface; bottom is title (H3) and one sentence. Equal heights within a row.

### Keep it honest
* **Confidence Level**: Requirement
* **Constraint**: Fictional products, people, logos, ratings and numbers must be labelled as samples or left out. Never invent testimonials or customer logos for a real product. A polished page with fake proof is still a failure.
